<objective>
Fix `buildRunnerFromToolTemplate` non-codex branch: it currently reconstructs `resume.args` from scratch as `["--resume", "{sessionId}", ...options]`, silently ignoring whatever the template declared. Pi's template declares `["--resume", "{sessionId}", "--dangerously-skip-permissions"]` — the current code happens to produce the same result for pi, but the mechanism is wrong and will silently break any runner whose template differs.

The fix: use `applyTemplate` on `template.sessionId.resume.args` to apply `{sessionId}` substitution without reconstructing the array. Add a comment explaining why codex is special-cased.

Purpose: Ensure all non-codex runners (pi, claude, future runners) have their template-declared resume args respected.
Output: Modified `agent-tool-presets.ts` non-codex resume branch, updated/new test for template preservation.
</objective>
