<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wizard→filesystem | writeEditableConfigAtomic writes to operator's config path; input comes from future wizard prompts (Phase 6+) |
| wizard→runtime process | ensureDaemonNotRunning reads PID/monitor state; read-only, no mutation |
| operator→wizard | ensureTTY gates interactive access; non-TTY callers are blocked at entry |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-03 | Tampering | writeEditableConfigAtomic — partial write on crash | mitigate | temp+rename atomic pattern (fs.rename is POSIX atomic); SIGINT handler removes orphaned .tmp (D-03, D-08) |
| T-05-04 | Tampering | daemon running while wizard writes config | mitigate | ensureDaemonNotRunning blocks wizard entry; runtime and wizard cannot write config concurrently |
| T-05-05 | Spoofing / DoS | non-interactive env (CI) runs wizard and hangs | mitigate | ensureTTY checks process.stdin.isTTY === true and exits(1) immediately; no readline is ever opened |
| T-05-06 | Denial of Service | Ctrl+C leaves dangling process (Bun #21189) | mitigate | withWizardCleanup calls process.stdin.unref() before process.exit(130) (D-10) |
| T-05-07 | Denial of Service | Ctrl+C mid-write leaves orphaned .tmp | mitigate | SIGINT handler calls unlink(tmpPath).catch(() => {}) before exit; .catch() ensures exit(130) always runs even if unlink fails |
| T-05-08 | Information Disclosure | error messages leak internal paths | accept | Error messages name commands (clisbot stop, clisbot init), not file paths; low risk for local CLI tool |
</threat_model>
